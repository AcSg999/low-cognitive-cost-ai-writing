# Visual Reasoning · 用图替读者完成关系推理

## 目标与依据

让读者在一处看清原本散落在线性文字里的关系。Larkin 与 Simon 比较了信息相同的图与文字表示，指出空间位置可以减少查找和部分推理。分散注意研究提示，当关键解释分散在图、图例和远处正文中，读者还要花精力把它们合起来。工程图的价值取决于它是否让当前任务更容易完成。 [Larkin 与 Simon](https://doi.org/10.1111/j.1551-6708.1987.tb00863.x) · [Chandler 与 Sweller](https://doi.org/10.1111/j.2044-8279.1992.tb01017.x)

典型困难是多条路径同时展开、同一对象随时间改变、几个变量流向相异、反馈在图外才看得见，或图与公式的符号无法对应。先确定具体困难，再决定画什么。

## 选图与工作流程

1. 写明读完图应能完成的动作，例如“从旧记录追踪后续估值，并指出哪一个 Q 被训练”。在模型里找到要保留的关系。若一句话或一张表已能完成任务，直接采用。
2. 为每类边写出含义。区分数据依赖、执行顺序、因果、梯度或参数同步、定位索引和正文导航。含义变化时用标签、明显线型或相邻图注说明。因果边还要能交代条件。
3. 决定图的尺度。总图回答“目前在哪个分支、下一段为什么出现”。局部图回答“这一处怎样运作”。先让总图节点能指向小节，再围绕困难画局部。总图连线若表示讲解路径，在读者开始追踪它的地方明确说明，尤其当图形外观像训练流程时。保持名称、符号与阅读方向连续。图文来回迭代，发现无法解释的边时回到 [Knowledge Modeling](knowledge-modeling.md)。
4. 布局、渲染、跟读。先摆主轴、组框和对齐，再安排短的分叉与汇合。按正文宽度检查字、边、交叉、色觉差异和链接入口。让正文负责因果、假设或演算，让图负责位置、关系或变化。局部必要说明尽量贴近对应节点。

| 关系与读者任务 | 常用形式 | 容易踩的坑 |
| --- | --- | --- |
| 按主题或章节恢复位置 | 总览图、概念图 | 节点多却无主轴，或只把标题画成盒子 |
| 步骤、判断与循环 | 流程图 | 箭头表示发生顺序时又被当成因果 |
| 输入、变换、去向或汇合 | 数据流图 | 把被训练对象的索引画成目标算式的输入 |
| 干预、影响和反馈 | 因果图 | 把相关、先后或理论上可能的影响标成必然 |
| 主体间先后、同步和等待 | 时序图 | 图上说的是执行先后，正文却拿它解释数据依赖 |
| 同一口径下的比较 | 对照表或并排图 | 两边单位、阈值、尺度不一致 |
| 概念先修或导出关系 | 知识依赖图 | 向上追溯太多层，挡住当前问题 |
| 几何、控制或物理量的变化 | 坐标图、曲线、结构示意 | 未交代轴、单位、正方向和适用范围 |

## 布局、工具和交付

- 算法、架构和数据流优先 Graphviz。用 dot、cluster 和 rank=same 管主轴、分组和对齐。用浅底组框、稳定的节点形状和少量语义颜色。箭头尽量走短且避免穿过文字。无标签时可试正交线，边带标签或端口时复核，改用 polyline 或 spline 也可以。命令行可执行 **dot -Tsvg input.dot -o output.svg**。环境缺 CLI 时可用 Graphviz WASM。 [Graphviz 走线文档](https://graphviz.org/docs/attrs/splines/)
- 需要手工控制端口、分区和圆角正交线时，draw.io 可保留原格式。参考 PNG 若包含图源数据，可以尝试编辑后读取布局规则。Intel Coach 的 SAC 图用浅底组框区分 V、Policy 与 Q，颜色区分输入输出和运算。模仿的是布局决策，算法节点需要依据当前版本。 [draw.io 内嵌图源说明](https://www.drawio.com/docs/manual/export/xml-in-png/) · [Intel Coach 的 SAC 图](https://intellabs.github.io/coach/components/agents/policy_optimization/sac.html#network-structure)
- 容易维持的简单关系可用 Markdown 表或目标环境支持的 Mermaid。几何和定量图选适当的 SVG、LaTeX 或绘图库。复杂图交付可编辑源和可直接显示的渲染件，按需要给可读图注或等价文本。真实图例只解释图中确实出现的编码。没有工具时保留可编辑表达并说明验证范围。

## 使用条件、常见失败与质量标准

长文遇到有不同读者入口的多个分支时，总览图通常有价值。局部图适合有真实分叉、汇合、反馈或时点分化的机制。很短的定义、已经能直接读懂的公式或三列简单比较，可用文字和表完成。同一文档图的数量由阅读任务决定。

常见失败包括同一箭头混用三种含义、图过密、文字逐节点复述、必要符号只在站远才看得到的图例中、同一角色换字母、可编辑源和渲染不对应。实际检查用题目驱动。例如“沿图指出终止时哪个分支失效”，若图的任务需要给出这项条件，就把终止标记连到作用处，并由正文解释原因。

每张交付图要能回答它的读图任务。图内和正文的变量、单位、版本与方向一致。总图能通往局部，图注说明适用条件或读法。渲染在正文宽度和可用的窄屏下验证。图片内链接可能受阅读器限制，重要入口还要有正文链接。
