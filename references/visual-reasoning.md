# Visual Knowledge Engineering · 视觉知识工程

把知识模型里的关系做成准确、可编辑、可渲染的视觉资产。图的价值在于让相关对象和它们的联系同时可见，减少读者在段落之间寻找、匹配和重建的工作。将关键标注放在关系发生的位置。 [Larkin 与 Simon，图形与文字表示](https://doi.org/10.1111/j.1551-6708.1987.tb00863.x) · [Chandler 与 Sweller，分散注意](https://doi.org/10.1111/j.2044-8279.1992.tb01017.x)

| 工作目标 | 图要帮读者完成的事 |
| --- | --- |
| **Cognitive Visualization** | 首次阅读就看清变量来源、角色、次序或对照关系 |
| **Algorithm Visualization** | 追踪算法结构、数据流、模块交互、执行和更新过程 |
| **Knowledge Mapping** | 把概念、依赖和关键机制放进一张可定位的整体地图 |
| **Retrieval Visualization** | 重新打开文章时，从总图找回局部，再通过局部图恢复机制 |

四种目标由同一个视觉引擎承担。一张图可以同时服务首次理解和后续复习，前提是两者都能沿图完成具体任务。

## 视觉工程流程

1. **Visual Need Detection · 需求检测。** 每次技术写作都查看知识模型。主动识别多阶段执行、组件传递、网络和系统架构、公式多源输入、状态转移、时序、反馈、概念依赖、算法结构差异和长文的恢复入口。Algorithm、Deep Dive、Tutorial 和科研机制解释优先检查流程、数据流、架构和核心机制。问清读者要同时记住哪些对象、时点和联系。PPO 的更新次序、SAC 的目标来源，即使能用一段文字说完，也可能因图而明显更易追踪。
2. **Visual Planning · 计划。** 给每幅图写出一个读者任务、图形类型、正文位置和关系语义。例如“从旧记录找到两个实测输入和拟合位置”。长文优先考虑一张总图，局部图只画难跨的机制。正文承担条件、推导和反例。若候选只比较少量同口径指标、重复已清楚展示的关系，或受到用户规定的格式限制，记录省略理由。计划可保留在写作工作记录里，正文仍以读者任务为主。
3. **Diagram Construction · 制作。** 用知识模型确定节点和边，再选工具。先定主轴、分组和层级，接着处理对齐、走线和标签。颜色、形状与线型保持同义，关键区别同时用标签或线型表达。保留能改节点、连线和标签的源。
4. **Technical Verification · 技术核对。** 沿每条边读出它的含义，核对起点、终点、方向、时间、条件及证据。逐项对照公式符号、单位和算法版本。输入目标计算、指定更新位置、执行先后、因果影响、梯度与参数同步各有语义。混用时分别编码并给图例。若一条边无法解释，退回 [知识建模](knowledge-modeling.md) 核对机制。
5. **Rendering & Inspection · 渲染检查。** 用实际工具产出图，打开观察中文字体、裁切、箭头相交、节点遮挡、对比度和标注大小。至少在目标正文宽度读一遍，能预览窄屏时也检查。渲染受限时标明实际检查的部分。
6. **Document Integration · 正文嵌入。** 将图插在解释关系的位置。正文先说从哪里看，以及要对照哪一步，再补图外的条件和推导。相对路径从 Markdown 文件所在目录计算。检查图确实作图嵌入、源链接能打开、图片和图注在目标阅读器中显示。
7. **Retrieval Integration · 恢复入口。** 长文用总图定位各机制，再从它附近进入局部图。复习题或公式引用可以回到正文已有图。实际走一遍“找到图 → 读出关系 → 回到结论”，用 [知识恢复](knowledge-retrieval.md) 的任务检查入口。

## 图形和工具选择

| 需要展示的关系 | 推荐工具和交付 | 需要核对 |
| --- | --- | --- |
| 简单流程、时序和状态转换 | Mermaid。可内嵌 Markdown，也可留下独立源并导出图 | 状态、事件和顺序能否直接读出 |
| 复杂有向图、依赖和数据流 | Graphviz。保存 DOT，渲染 SVG 或 PNG | 方向、聚类、边标签和图内符号 |
| 复杂系统、神经网络、模块图和精细布局 | draw.io。保留 .drawio，再导出 SVG 或 PNG | 端口、层级、跳线、重复模块与对齐 |
| 精确数学图和工程示意 | SVG 或能生成 SVG 的绘图代码 | 坐标、单位、正方向、几何比例和适用范围 |
| 同口径标量比较或简短规则 | Markdown 表或简短文字 | 表中是否已有读者要比较的全部维度 |

Graphviz 的层级图可用 dot、cluster 和 rank=same 定主轴和分组。带边标签时打开预览检查走线。可以执行 **dot -Tsvg input.dot -o output.svg**，环境中也可以使用 Graphviz WASM。draw.io 适合手工控制端口和圆角正交布局。参考图的视觉组织可以借用，算法节点按当前版本核对。 [Graphviz 走线](https://graphviz.org/docs/attrs/splines/) · [Intel Coach 的 SAC 图](https://intellabs.github.io/coach/components/agents/policy_optimization/sac.html#network-structure)

## 交付与降级

一篇 Markdown 可在 assets/ 下保存 sac-target.svg、sac-target.dot 或 algorithm-overview.drawio，并把读者要看的 SVG 或 PNG 嵌进正文。Mermaid 在目标 Markdown 能渲染时，可在同一个代码块完成编辑和显示。若阅读器不支持 Mermaid 或支持情况未知，优先生成它能直接显示的 SVG 或 PNG，并同时保留可编辑源。截图无法保留节点和连线的编辑能力，动态界面的实测截图可作为单独证据。

工具确实不可用时，交付可编辑源和必要的简短读图路径，并明确哪幅图尚未渲染。已经嵌入的图可以通过客户端读图则继续使用。未生成图的链接、仅有的绘图建议和未经打开的预览声明都不能作为完成渲染的证据。

## 视觉交付检查

- [ ] 已主动评估视觉候选，并为省略的重要候选记录具体原因。
- [ ] 重要算法关系已表达，读者无需从分散段落中重新拼出关键关系。
- [ ] 纯文字成本明显高的段落有对应图或明确的工具限制。
- [ ] 图实际生成并嵌入正文，降级项明确注明验证范围。
- [ ] 图片和源文件路径能从正文解析。
- [ ] 已在目标阅读器或可说明范围的预览中打开，图中文字与连线可读。
- [ ] 公式、变量、节点、边和条件与算法来源一致。
- [ ] 图与正文用相同术语，读图动作和新增解释在相应位置。
- [ ] 保留 DOT、Mermaid、.drawio、SVG 或绘图代码等可编辑源。
- [ ] 核心图能帮助读者找回机制，总图和局部之间有正文入口。

## 技术写作实例 · 从经验复用总图到 SAC 目标

总图的读者任务是看清 PPO 与 SAC 在哪里复用采到的经验。局部图的任务是定位一次 SAC 更新的两个输入和被拟合的旧状态动作对。总图先建立比较维度，局部图再让读者沿数据来源定位公式。在正文中把总图连到局部图，再连到成本对照。
