# Teaching & Explanation · 设计理解路径

## 目标与依据

让目标读者在进入一段新推理时，手上已有足够的对象、条件和尺度。文章要承担关键的中间演算、关系重建和边界比较，使读者可以把精力用在理解与迁移上。完整示范、专长反转与分散注意的研究提供了使用引导的理由，也提示引导强度需要随任务和经验变化。 [完整示范实验](https://doi.org/10.1207/s1532690xci0201_3) · [专长反转](https://www.tandfonline.com/doi/abs/10.1207/S15326985EP3801_4) · [分散注意](https://doi.org/10.1111/j.2044-8279.1992.tb01017.x)

认知障碍往往能定位到一个点。读者知道名词却分不清角色，懂每个量却想不出如何相互作用，或者跟得上个别步骤却记不住整条链。在选表达形式前，明确卡在哪里。

## 决策流程

### 按读者当前的任务选择开头

先问读者读完开头需要得到什么。是一个可以继续推演的机制结论、一项待解释的观察、一个比较基准、一张整体地图，还是一个可以检验的研究问题？用这个需求选择开头，再沿[知识模型](knowledge-modeling.md)中的依赖安排后续解释。

| 知识任务 | 更适合的开头 | 后续如何展开 |
| --- | --- | --- |
| 明确的机制问题 | 直接给出机制结论 | 从决定结果的那一步往下解释，交代成立条件和边界 |
| 解释某个现象 | 现象 → 原因 | 先说看到了什么，再用证据或模型说明为什么会出现。教学假设就地标明 |
| 反直觉的问题 | 直觉预期 → 矛盾 → 解释 | 说清读者原本会怎样预测，找出实际结果不同的原因。核对尺度、口径和假设 |
| 两种算法的比较 | 先给核心差异，再解释 | 选对读者最重要的比较维度，让两种算法在同一任务或输入下各走一遍 |
| 完整的知识教程 | 从整体结构开始 | 先交代学习目标、主要模块和最终结果，再按依赖进入局部 |
| 探索性研究问题 | 问题 → 假设 → 分析 | 说清要检验什么、哪些证据能区分假设，以及分析能支持到什么程度 |

这些是可选入口。同一主题换一个读者任务，开头就可能变化。比较 PPO 与 SAC 怎样复用经验时，可以先点出“PPO 在本轮复用轨迹，SAC 跨轮回放旧转移”，再跟踪同一次交互。解释“为什么少采样反而可能更慢”时，可以先写出“环境步更少，应该更快”的预期，再对照达标耗时，找出单次更新成本和更新次数的作用。

进入具体段落时，标出读者此刻已有的前提，再检查他还要自行补哪个对象、关系或条件。能确定结论时，试着用一句话复述它，找出略过的中间一步。研究问题仍开放时，检查读者能否从观察走到一个可检验的假设。抽象对象难以想象时，可以先走完一个最小实例，再把实例映射到通用关系。

### 问句提出后，就地交付回答

先判断问句是否代表读者真的需要解决的疑问。它若只负责预告下一段、重复小标题或制造悬念，就把它改成能推进解释的陈述。若决定读者下一步怎样理解，就把问题和回答放在同一个解释单元里。段内提问后先给实质判断或关键原因，再举例推演。标题若问一个已经能回答的问题，在小节首段用一句完整的话交代结论和关键原因，然后再放定义、算例、公式或表格。现象或反直觉的开头可以先用一句必要的观察或对照，紧接着在同一首段指出原因。若主问题已在导言回答，正文小节默认用具体机制、发现或结果作标题。保留的问句要有独立用途，例如标出一个需要现场解决的反直觉点。改写时也要重审原稿留下的问句标题和悬空转场，必要时调换段落。当问题出在小节内部，回到小节里修。

例如，问“为什么 SAC 少采样却可能更慢？”之后，先写“多做梯度更新所花的时间，可能超过省下的环境交互时间”，再算采样和更新各用了多少秒。价值信号传播适合用于解释更新进展，放到这个成本判断之后。节末想从回放转到覆盖时，可以写“回放很少见过这个动作时，评分主要来自网络外推”，直接把两段的关系说出来。

探索性研究问题可以保留开放。就地说清现有证据支持什么、哪一步仍待检验，再进入假设和分析。自测题按复习目的保留清楚的答案或核对入口。

### 外化、预判和压缩

- **例子**。选择能固定其余条件的情境。比较两个版本时写明什么变了、什么保持不变、结果差在哪里。若真实案例多量齐变，可以先构造小反事实，明确它是教学算例。如果结果含随机性，先分清想解释的是单次观测变化、输出分布变化还是均值变化。单次结果差异可以引出问题，受控条件下的分布或均值更适合定位机制。
- **类比**。只在读者缺初始直觉时引入。说明映射关系和首个会失效的地方。“一步视频”可以帮助理解固定的观测。估值的可靠性需要按数据覆盖另行解释。
- **公式**。先说要计算什么，定义各量，区分形似记号。沿对象、结构、局部代入顺序讲。若要引入均值，先说清对谁取平均、哪些量固定。处理边界时尽量让读者看到哪一项消失。
- **预判提问**。停在机制拐点，问读者能否在只知道前文的情况下解释下一步。会改变结论的合理疑问用上一节的规则处理。独立的兴趣问题留到真正用到时。
- **压缩总结**。当读者已经看完机制，保留可以用于下一段或新情形的一条关系。比如“增加回放更新能重复使用已知证据。要为少见动作补直接依据，仍需覆盖这一带的交互。”换比较尺度时，小表通常比重述导言更容易使用。

图文要共同排顺序。难点来自两条输入与一处汇合时，让图先交代路线，让正文解释终止条件或举例算出结果。只需说明一条约束时，可直接写一句。详细选图见 [Visual Reasoning](visual-reasoning.md)。

## 使用条件、失败模式与输出

对已有专业背景的读者，可以直接从关键式子或实现差异开始，但仍要承担其上下文中新增的角色区分。初读者先获得局部直觉和一个完成的例子。操作型任务优先明确起点、动作、预期看到的结果和失败时该查哪里。查阅任务优先准确、可检索的条目。自然地省略无用的类比、练习、图和章节标题。

失败信号包括公式先于对象，多段叠加仍找不到因果，从例子学到错误的普遍规律，读者需要跨节来回查条件，或每节都出现相同的问答和总结。遇到缺条件或事实冲突回知识模型，遇到布局导致反复寻找则重排或改图。输出是可走通的一条正文路径，可在内部用段落职责记录关键转折。检查至少一处最难推理已经走完，数字能复算，结论与限制出现在相近位置。成稿应带着读者做出结果。

## 技术写作实例 · 两次抽样和改策略

“第一次抽到的后续价值是 0.2，过一阵变成 0.8”能说明同一记录可以算出不同目标。若要进一步解释策略变化，采用固定记录、目标网络和熵权重的两动作对照，再交换两动作概率。两种分布的熵相同，平均目标的差异可归到策略对现有 Q 评分的重新加权。先解释固定参数时单次目标仍可随机波动，再计算均值差，就能让读者区分波动与机制。完整结果见 [PPO vs SAC 案例](examples.md)。
